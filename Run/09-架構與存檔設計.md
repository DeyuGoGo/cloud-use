# 09 — M1 架構與存檔

2026-09-11，反映漫畫版實作。Godot 4.6.3 標準版；GDScript 演出＋JSON 章節資料，沒有 Ink。

## 場景與資料

`EveningTitle → FirstEvening → EveningTitle`。`SceneRouter.evening_resume` 決定是否讀回新版進度。舊的序章、日常與手機場景仍留在專案，不自動接入新版。

`story/first_evening.json` 的 beats 是單一執行來源。每拍具備 id、scene、time、bg、cast、speaker、text；kind 區分 scene／phone，thread 分聊天對象。action 表達具體動作。choices 是 label／value 陣列；when 引用較早的 choice id 與 value，決定該拍是否出現。shot 可指定多人同場插畫。

`visual` 可指定 `run_record`、`invite`、`feed`、`photo_preview`、`selected_photo`。`visual_data` 保存該拍的可配置文字、圖片或照片版本。兩者不繼承到下一拍，避免普通場景留著上一張卡片。圖片拍允許 `text` 為空，前進一次即保存下一拍；閱讀紀錄使用 `visual_data.log_label` 或短類別名稱。

本輪語句與視覺修訂保留 120 個 ID 的順序及三處選擇 value，原 M1 游標可繼續使用。字數不是內容相容性的依據。

`comic` 描述整頁：atlas、grid、panels 與 through；panel 包含 frame、speaker、text、alt，可用 caption_outside 將字句放到圖外。後續同頁來源以 comic_parent 指回起始 ID。Runner 驗證分組不跨分支、手機、原 visual 或坐下／接水四個保護拍，再建立來源索引對照。舊存檔落在頁中時重建完整頁，前進一次保存 through 後的位置；只在展示層合頁，不改存檔版本或 source cursor 意義。

`EveningComic.present(data)` 同時顯示一至四格，等比選取圖集區域，字句由原生 Label 排版。漫畫頁隱藏原背景立繪和大對話框，離開即清除。閱讀紀錄包含已讀頁的 alt 和實際短句，不把隱藏來源拍再列一遍。

`EveningRunner` 負責呈現、進度、選擇、閱讀紀錄與暫停。`EveningAlive` 接收當前拍、已走過的拍、所選合照與社群偏好，建立動態牆、收件匣和私訊；不接收尚未到達的故事。瀏覽狀態交回 Runner 控制前進入口，不另設故事游標。頭像圈、圖示沿用舊 Alive 的視覺元件，不接入舊原型的角色資料與路由。

`EveningSound` 依場地播放低音量合成環境音，具備靜音與短音效。一般演出資料沒有可執行腳本。

`EveningRunRecord.present(data)` 是可重用的跑後畫面。`visual_data` 可傳 title、distance、unit、location、date、time、duration、duration_label、pace、company、note，以及 terrain（river／city）和正規化路線點 route。缺少可選數值就不顯示。底圖是引擎原生示意，不讀外部地圖或 GPS。

超商動作使用 `art/m1/store_actions.png` 四格 AtlasTexture。store_01／02 站姿、03 坐下、04 遞水、05／06 拿到水、07 飲水後；離開該段即恢復通常場景。鏡頭依拍 ID 重建，不增加存檔欄位。提交立即前進並保存乾淨的下一拍，再播放短轉場；中途關閉後重讀會顯示已完成的結果。所有入口共用 `_next`，轉場期間防重複提交。

## 新版存檔

`EveningSave` 是靜態服務，API 為 exists/read/write。主檔 `user://first_evening_v1.json`，欄位為 version:1、cursor、choices、complete、settings.muted，以及選用的 social.liked／social.saved。

- 新遊戲進入第一拍時不寫檔；玩家完成一個段落後才保存乾淨位置。
- 寫入 tmp，flush 並重新解析驗證，再備份有效舊主檔、rename。
- 主檔格式或版本不合法時退回有效 bak，兩者都不可用則視為無新版存檔。
- 該版本只接受合法欄位型別，不執行存檔內容。
- 舊 `run_save.json` 不刪除、不遷移；M1 用獨立命名避免破壞既有日常進度。
- 選擇保存在 choices；讀回後依條件重建實際閱讀紀錄。新版沒有 Profile 或多格選單。
- Alive 按讚、收藏以貼文 ID 對應布林值保存；只更新社群偏好，不移動故事位置。舊 v1 缺少 social 時補空字典；偏好損壞時清理無效項目，保留有效故事進度。

## 驗證與後續

系統測試在獨立 temp project／APPDATA 中檢查原子保存、失敗回退、legacy 保留及聲音。整合測試透過真實按鍵事件與推進函式檢查分支、焦點、保存和續讀。`--m1-test` 走完全部八條路徑且禁止寫入玩家存檔。

後續若正式增加章節或更改游標結構，要提升存檔版本並設計遷移。Profile、多手動格、回憶、日常事件池與更多手機功能，在內容真正需要時另立工作項目。
